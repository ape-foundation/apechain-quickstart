# Start an ApeChain project

This file tells a coding agent how to create a new project from the ApeChain Quickstart and get it to a working state: contract deployed to Curtis testnet, frontend running, wallet connecting through Glyph.

Raw URL (for agents outside the repo): https://raw.githubusercontent.com/ape-foundation/apechain-quickstart/main/SKILL.md

## 0. Check whether the project already exists

If `./packages/nextjs/scaffold.config.ts` exists in the current directory **and** it lists `chains.curtis` in `targetNetworks`, you're already inside an ApeChain Quickstart project. Skip to step 4.

If it exists but targets other chains, it's a plain Scaffold-ETH 2 project, not this kit. Ask the user whether to scaffold a fresh ApeChain project next to it instead of converting it.

## 1. Check prerequisites

```bash
node --version      # needs >= 22.10
corepack enable     # provides Yarn 4 (version pinned in package.json)
forge --version     # Foundry, only needed for the default Foundry workflow
git --version
```

If Foundry is missing and the user wants it, point them to `curl -L https://foundry.paradigm.xyz | bash && foundryup`. Don't run installers that modify the user's shell profile without asking.

## 2. Clone the template

Ask the user for a project name if they haven't given one (kebab-case, e.g. `ape-raffle`). Then:

```bash
git clone --recurse-submodules https://github.com/ape-foundation/apechain-quickstart.git <project-name>
cd <project-name>
git remote rename origin upstream   # keep the template as `upstream` so updates can be pulled later
yarn install
```

- `--recurse-submodules` is required: `forge-std`, `openzeppelin-contracts` and `solidity-bytes-utils` are git submodules under `packages/foundry/lib`. If they're empty, run `git submodule update --init --recursive`.
- Don't delete `.git` to "start fresh": it breaks the submodules. Keep the history, or squash it later.
- If the user has a GitHub repo for the project, add it with `git remote add origin <url>`. Don't push unless asked.

## 3. Make it the user's project

Do these edits in one pass, then run the checks in step 6.

### 3a. Pick a contract framework

Foundry is the default (root `yarn deploy`, `yarn test`, … run Foundry). Hardhat is available through `hardhat:`-prefixed commands. Ask the user which they want if they haven't said. If they want only one:

- **Foundry only:** delete `packages/hardhat`, remove every `hardhat:*` script from the root `package.json`, and drop `&& yarn hardhat:format` / `&& yarn hardhat:lint` from the root `format` and `lint` scripts.
- **Hardhat only:** delete `packages/foundry`, remove every `foundry:*` script, point the un-prefixed scripts (`account`, `compile`, `deploy`, `generate`, `test`, `verify`, `flatten`, `account:import`, `account:reveal-pk`, `format`, `lint`) at their `hardhat:` equivalents, remove the three submodule entries from `.gitmodules`, and run `git submodule deinit -f --all` before deleting the folder.

Run `yarn install` again after removing a workspace.

### 3b. Rename the project

| What | Where |
| --- | --- |
| Package name | `name` in the root `package.json` |
| Page title + description | `metadata` in `packages/nextjs/app/layout.tsx` |
| Title template | `titleTemplate` in `packages/nextjs/utils/scaffold-eth/getMetadata.ts` |
| Header brand text + logo alt | `packages/nextjs/components/Header.tsx` |
| Landing page copy | `packages/nextjs/app/page.tsx` |
| README | Replace the quickstart intro with the project's own; keep the commands section |

### 3c. Replace `YourContract` with the user's contract

`YourContract` is a placeholder greeting contract. When the user describes what they want to build, rename it everywhere rather than adding a second contract next to it:

**Foundry**
- `packages/foundry/contracts/YourContract.sol` → `<Name>.sol`
- `packages/foundry/script/DeployYourContract.s.sol` → `Deploy<Name>.s.sol` (constructor args go in `run()`)
- `packages/foundry/script/Deploy.s.sol` imports and runs that script
- `packages/foundry/test/YourContract.t.sol` → `<Name>.t.sol`

**Hardhat**
- `packages/hardhat/contracts/YourContract.sol` → `<Name>.sol`
- `packages/hardhat/deploy/00_deploy_your_contract.ts` → `00_deploy_<snake_name>.ts` (update `artifacts.<Name>`, `args`, `tags`)
- `packages/hardhat/test/YourContract.ts` → `<Name>.ts`

**Frontend**
- `packages/nextjs/app/page.tsx` mentions `YourContract.sol`
- Any `contractName: "YourContract"` in hooks
- `packages/nextjs/contracts/deployedContracts.ts` is regenerated by deploy. Don't hand-edit it; until the first deploy, `contractName` type errors for the new contract are expected.

Before writing contract code, read the matching skill in `.agents/skills/` (e.g. `openzeppelin`, `erc-721`). Follow the conventions in `AGENTS.md`.

## 4. Deployer account (user action)

`yarn generate` and `yarn account:import` prompt for a keystore password, so the agent can't run them. Ask the user to run one of these in their terminal (in Claude Code, typing `! yarn generate` runs it in the session):

```bash
yarn generate          # new encrypted keystore in ~/.foundry/keystores
yarn account:import    # or import an existing private key
```

Hardhat: `yarn hardhat:generate` / `yarn hardhat:account-import` (stores an encrypted key in `packages/hardhat/.env`).

Then run `yarn account` yourself to get the deployer address and balance. If the Curtis balance is 0, ask the user to fund it at https://curtis.hub.caldera.xyz and wait for them to confirm.

**Never** read, print or copy `.env` files, keystores or private keys, and never run `yarn account:reveal-pk`. Each package documents its variables in `env.example`; read that instead.

## 5. Deploy to Curtis (user action)

Deploying decrypts the keystore, so it prompts for the password too. Ask the user to run:

```bash
yarn deploy                     # Foundry, Curtis is the default network
yarn hardhat:deploy --network curtis   # Hardhat
```

Afterwards, confirm `packages/nextjs/contracts/deployedContracts.ts` has an entry under chain id `33111` for the new contract.

There's no local chain in this kit: Glyph is an embedded wallet that can't connect to localhost. Don't try `yarn chain`, `anvil` or `hardhat node` as a substitute for Curtis.

## 6. Verify it works

Run these yourself and fix anything that fails:

```bash
yarn test               # or: yarn hardhat:test
yarn next:check-types
yarn lint
```

Then start the frontend with `yarn start` (http://localhost:3000). Tell the user to connect with **Glyph** and try the contract on the **Debug Contracts** page.

Optional, if the user has an Etherscan V2 API key in their package `.env`: `yarn verify --network curtis` (Hardhat: `yarn hardhat:verify --network curtis`).

## 7. Hand off

Summarize for the user:

- Project path, framework chosen, contract name and its Curtis address
- What they still need to do (fund, deploy, set `NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID` in `packages/nextjs/.env.local` before production)
- Mainnet is `yarn deploy --network apechain`; ask before deploying there since it spends real APE

From here on, `AGENTS.md` in the project root is the reference for hooks, components, styling and the skill index.
